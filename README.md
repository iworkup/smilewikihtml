# Smile Wiki HTML

Стартовый HTML-шаблон wiki-проектов на готовых компонентах Bootstrap v6, установленном через npm. Используется **6.0.0-alpha.1**: это предварительный выпуск, версия зафиксирована в package-lock.json. Собственные стили и изменения дизайна требуют отдельного разрешения.

## Запуск

Нужен Node.js 22.12+ (либо 24 LTS) и npm.

```sh
npm ci
npm run dev
```

Vite слушает все сетевые интерфейсы. HTML автоматически перезагружается при сохранении, изменения импортируемых CSS/JS обновляются через HMR. Отдельный LiveReload-сервер не нужен.

Постоянные адреса разработки:

- На этом компьютере: http://localhost:5173/smilewikihtml/
- С другого устройства в той же сети: http://smilewikihtml.local:5173/smilewikihtml/

`npm run dev` и `npm run preview` автоматически объявляют `smilewikihtml.local` через mDNS. Имя не зависит от имени компьютера или DHCP-адреса сервера. Сервер может работать на macOS, Windows или Linux; публикация выполняется npm-библиотекой, без переименования компьютера. Не запускайте копии проекта на разных компьютерах в одной сети одновременно: имя должно принадлежать одному серверу. Порты фиксированы; занятый порт вызывает ошибку.

### Доступ с Windows и Linux

Устройства должны находиться в одной сети без изоляции клиентов. На сервере разрешите Node.js входящие TCP 5173/4173 и mDNS UDP 5353 в частной локальной сети.

- **macOS:** разрешение `.local` обычно работает через встроенный Bonjour.
- **Windows:** откройте адрес в браузере и проверьте `curl.exe http://smilewikihtml.local:5173/smilewikihtml/`. Работа mDNS зависит от версии и сетевых политик Windows; при блокировке используйте вариант с hosts ниже.
- **Linux:** нужен включённый mDNS resolver. Для Debian/Ubuntu с Avahi: `sudo apt install avahi-daemon libnss-mdns`, затем `sudo systemctl enable --now avahi-daemon`. В `hosts:` файла `/etc/nsswitch.conf` модуль `mdns4_minimal [NOTFOUND=return]` должен стоять перед `dns`. Проверка: `getent hosts smilewikihtml.local`. Если используется systemd-resolved, настройте mDNS в нём согласно документации дистрибутива, не смешивая настройки вслепую.

**Надёжный запасной вариант для любой из этих ОС:** закрепите IP сервера DHCP-резервацией на роутере и добавьте на каждом клиенте строку `IP_СЕРВЕРА smilewikihtml.local` в hosts (подставьте реальный LAN IPv4, не 127.0.0.1):

- Windows: `C:\Windows\System32\drivers\etc\hosts`, редактор от администратора; после изменения `ipconfig /flushdns`.
- Linux/macOS: `/etc/hosts`, нужны права администратора.

Это сохраняет одинаковый URL даже при отключённом mDNS. Без mDNS либо записи hosts гарантировать разрешение `.local` на произвольном Windows/Linux устройстве нельзя. Запись hosts обновляется при переносе сервера, поэтому DHCP-резервация обязательна для этого варианта.

Источники: [nss-mdns](https://github.com/avahi/nss-mdns), [Avahi](https://avahi.org/).


- Локально: http://localhost:4173/smilewikihtml/

- GitHub Pages: https://iworkup.github.io/smilewikihtml/

## Структура

- `smilewikihtml/` — исходный HTML, JS и будущая разрешённая кастомизация.
- `docs/` — результат сборки для GitHub Pages; вручную не редактировать.
- `node_modules/` — npm-зависимости, исключены из Git.
- `.github/workflows/deploy.yml` — сборка и публикация при пуше в `main`, а также ручной запуск.

В настройках репозитория Pages используется источник **GitHub Actions**. CI выполняет `npm ci`, собирает `docs/` и публикует артефакт. Для публикации достаточно пуша в `main`.

Правила дальнейшей работы: [AGENTS.md](AGENTS.md).

## AI-инструкции Bootstrap

Из [официальной страницы](https://getbootstrap.com/docs/6.0/getting-started/ai/) установлены все 11 скиллов в `~/.codex/skills/` и сохранены в `.agents/skills/` для репозитория и gigacode. Codex автоматически увидит установленные скиллы со следующего сообщения. Индекс документации — `.agents/bootstrap/llms.txt`; полный текст доступен по https://getbootstrap.com/llms-full.txt и загружается только при необходимости.

Скиллы взяты из `twbs/bootstrap`, ветка `main`, 25 октября 2026, commit `2bb544eb426e9b1e019c2a98798e0002b8a41d35`. Для конкретной разметки проверять документацию версии 6.0.0-alpha.1. Код скиллов — MIT, документация Bootstrap — CC BY 3.0.

В `.gigacode/settings.json` подключён Chrome DevTools MCP с изолированным профилем. Для его первого запуска нужны Chrome, Node.js и доступ к npm. Проверки можно поручать gigacode: открыть адрес, проверить desktop/mobile, интерактивность, консоль и сеть, затем вернуть краткий отчёт. Не отключать проверки, если MCP недоступен: выполнить их через Chrome MCP в Codex.

## Верхняя панель

Кнопка-лупа справа открывает стандартный Dialog: поиск фильтрует разделы текущей страницы без сервера. Пустой запрос скрывает результаты; переход к результату закрывает диалог. Меню темы предлагает светлый, тёмный и системный режимы, сохраняет выбор в localStorage; без доступа к хранилищу работает до перезагрузки. По умолчанию тема системная и автоматически следует настройкам ОС.

На широком экране слева расположена навигация сайта, справа — оглавление страницы с Scrollspy. На экранах уже lg обе панели открываются через стандартные Drawer. Используются только компоненты и utility-классы Bootstrap, без собственного CSS.

Авторизация демонстрирует два состояния шаблона без сервера: «Войти» показывает имя «Пользователь», значок пользователя и пункты «Профиль» / «Выйти»; «Выйти» возвращает гостевое меню. После перезагрузки снова показано гостевое состояние. «Профиль» и «Регистрация» выводят пояснение о демонстрационном пункте.

## Иерархия страниц в сайдбаре

Обе версии меню строятся из `navigationPages` в `smilewikihtml/main.js`: у страницы есть `title`, `href` и необязательный массив `children`. В шаблоне показана демонстрационная ветвь до 10 уровней, ведущая к существующим разделам страницы. Для реального wiki замените её своим деревом и адресами страниц. Вложенные списки отмечены вертикальными линиями; компактные строки без обводки используют только готовые utility-классы Bootstrap.
