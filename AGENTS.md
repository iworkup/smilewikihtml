# Правила проекта SmileWiki

- Использовать только готовые компоненты и utility-классы Bootstrap v6. Устанавливать Bootstrap через npm с точной версией и package-lock.json; сейчас доступна версия 6.0.0-alpha.1.
- Любая кастомизация дизайна, собственные CSS, переопределения Bootstrap, собственные UI-компоненты и дополнительные UI-библиотеки требуют отдельного разрешения пользователя. Сборочная инфраструктура не считается кастомизацией дизайна.
- Исходники шаблона и разрешённой кастомизации находятся в /smilewikihtml, результат сборки — в /docs. Не редактировать /docs вручную.
- node_modules не коммитить. Зависимости устанавливать через npm; для воспроизводимой установки использовать npm ci.
- Экономить токены и лимиты Codex: точечные чтения, краткий вывод, достаточные проверки без повторов. Максимально делегировать подходящую работу глобальному gigacode CLI, разбивая её на небольшие понятные задачи с критериями проверки. Проверять его результат перед применением.
- Каждую доработку проверять через Chrome MCP: интерфейс, адаптивность, интерактивность, ошибки консоли и сетевые запросы. При конфликте профиля завершать только экземпляр Chrome, использующий профиль MCP, и запускать его заново. Не просить пользователя закрывать браузер. По возможности передать проверки gigacode при наличии рабочего MCP; отсутствие MCP у gigacode не отменяет проверки Codex.
- Не выводить и не сохранять учётные данные.
- После каждой завершённой и проверенной доработки выполнять git add ., коммит с сообщением на русском языке и git push в подключённый origin.
- Публикация GitHub Pages выполняется workflow при каждом пуше в main. Не пушить производные коммиты сборки из CI.
- Фиксированные порты: dev 5173, preview 4173; strictPort обязателен. Адреса и инструкции поддерживать в README.md. Не подменять занятый порт случайным.
- Следовать официальным AI-инструкциям https://getbootstrap.com/docs/6.0/getting-started/ai/. Локальные копии всех 11 официальных скиллов: `.agents/skills/bootstrap-*/SKILL.md`; индекс документации: `.agents/bootstrap/llms.txt`. Читать только подходящий скилл и точечные страницы документации; не загружать llms-full.txt целиком в контекст.
- Для установки и Vite применять `bootstrap-v6-install` и `bootstrap-vite`, при исправлении старых классов — `bootstrap-v5-v6-migration`. Приоритет у требований пользователя: использовать готовый npm dist CSS без Sass-кастомизации; исходный Sass потребуется только после разрешения на кастомизацию. Не переносить разметку v5 в v6: например, кнопки используют `btn-solid theme-primary`, responsive-классы имеют префикс breakpoint, мобильная navbar использует Drawer. Сверять с документацией соответствующей версии.
- Gigacode настроен через `.gigacode/settings.json` на Chrome DevTools MCP с `--isolated`, то есть отдельным профилем. При запуске проверок разрешать необходимые инструменты, но не сохранять секреты в настройках.
